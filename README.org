* Inicio rápido

Todo se ejecuta en =127.0.0.1= con datos ficticios. No exponer la aplicación a Internet.

#+begin_src bash
export LAB_PASSWORD="$(openssl rand -hex 12)"
export LAB_USER_PASSWORD="$LAB_PASSWORD"

python3 -m venv .venv && source .venv/bin/activate
pip install -r app/requirements.txt

# Terminal 1: versión vulnerable
lab/run.sh vulnerable 5000

# Terminal 2: versión corregida + monitoreo
lab/run.sh secure 5001

# Terminal 3: pruebas y evidencias
python3 lab/pruebas/probar.py
python3 lab/pruebas/verificar_controles.py
#+end_src

La contraseña y la clave de sesión se pasan por variable de entorno y *no* se guardan en el
repositorio. El ejemplo anterior genera una contraseña aleatoria en la sesión de la shell:
las dos aplicaciones y las dos pruebas comparten el mismo valor sin escribirlo en un archivo.
Si no se definen, la aplicación genera valores efímeros y los imprime en la terminal.
Los archivos =app/lab_*.sqlite3= y =logs/= se ignoran en Git.

* Modo vulnerable

- =GET /buscar?q=...=: concatena el parámetro en la consulta SQL (SQLi).
- =POST /comentarios= + =GET /comentarios=: marca el contenido como seguro con =|safe= (XSS).
- =GET /expediente/<id>= y =GET /api/expediente/<id>=: sin verificación de propiedad (IDOR/BOLA).

* Modo corregido

- Consultas =LIKE ?= parametrizadas y validación de longitud.
- Autoescape de Jinja y cabecera =Content-Security-Policy=.
- Autorización por =owner_id= o rol =socio=, con denegación por defecto.
- Registro JSON de eventos, correlación por reglas y panel =/alertas= (Opción B).
- Token anti-CSRF por sesión en =/login= y =/comentarios=; se valida con
  =hmac.compare_digest= y se registra =CSRF_RECHAZADO=.
- Cabeceras =Cache-Control: no-store=, =Permissions-Policy= y
  =Cross-Origin-Resource-Policy= además de CSP y =X-Frame-Options=.

* Evidencias

Las evidencias de texto de las tres vulnerabilidades y los registros se regeneran con
=lab/pruebas/probar.py=. La evidencia de los controles añadidos se regenera con
=lab/pruebas/verificar_controles.py=. Los informes de ZAP se generan con
=lab/zap/scan.sh=; los incluidos corresponden al escaneo original y no se han vuelto a
ejecutar tras añadir el token anti-CSRF. Las capturas se toman con
=scripts/capturar.sh=; el modo interactivo usa =grim -g "$(slurp)"= y el modo automático
acepta una geometría explícita.

Las capturas de =capturas/documento/= ilustran el informe (endpoints, tres
vulnerabilidades antes/después, ZAP y el panel de alertas). Las de
=capturas/presentacion/= son un subconjunto preparado para la presentación
ejecutiva, que no se incluye en este entregable.

La comparación ZAP antes/después se regenera con:

#+begin_src bash
lab/zap/scan.sh http://127.0.0.1:5000 evidencias/zap
lab/zap/scan.sh http://127.0.0.1:5001 evidencias/zap/secure
scripts/capturar_figuras.sh
#+end_src

* Seguridad de la entrega

No se publican credenciales, claves, secretos, datos personales reales ni información
sensible. Todas las personas, clientes, RFC y montos son ficticios. El laboratorio está
aislado y no requiere servicios en la nube.
